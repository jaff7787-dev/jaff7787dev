# 인수인계 문서 (3) 기술 아키텍처와 빌드 방법

## 전체 구조

```
[원본 PDF] --extract.py(PyMuPDF)--> vocab.json (48일×50단어)
                                        |
[app_template.html] --build.py--+-------+
[Pretendard .otf]  --(fonttools 서브셋→woff2→base64)--+
                                        |
              +-------------------------+-------------------------+
              | index.html (저장소용: vocab.js 외부참조, PWA 링크) |
              | vocab.js                                          |
              | voca-quest.html (아티팩트용: vocab 인라인, 단일파일)|
              +---------------------------------------------------+
```

- 앱은 **한 개의 HTML** 안에 CSS/JS/폰트(base64 woff2)가 전부 들어있는 정적 페이지.
- 템플릿의 치환 토큰: `__FONT_REGULAR__`, `__FONT_XBOLD__` (base64 woff2),
  `__VOCAB_SCRIPT__` (`<script src="vocab.js">` 또는 인라인), `__PWA__` (manifest/icon 링크, 아티팩트에선 빈 값).

## 다시 빌드하는 방법

동봉된 `build-src/` 사용. 필요한 것: Python3 + `pip install pymupdf fonttools brotli`, 폰트 원본(저장소에 있음).

```bash
# 1) (데이터를 다시 뽑을 때만) PDF에서 추출 — 경로를 자기 환경에 맞게 수정
python3 extract.py           # -> raw.json 생성 후 정제 과정을 거쳐 vocab.json
# 보통은 동봉된 vocab.json을 그대로 쓰면 됨 (2,400단어 정제 완료본)

# 2) 앱 빌드 — build.py 상단의 SP(스크래치 경로)/REPO(저장소 경로) 변수를 수정
python3 build.py
# -> {REPO}/index.html, {REPO}/vocab.js, {SP}/voca-quest.html 생성
```

> extract.py/build.py 안의 절대경로는 이전 세션의 스크래치 디렉터리 기준이므로
> **이어받은 환경에 맞게 경로 변수만 고치면 됨**. 로직은 그대로 사용 가능.

### PDF 추출 로직 요점 (extract.py)

- 정답 페이지(짝수 페이지, "Day NN 정답")만 파싱. 텍스트에 섞인 제어문자 `\x01`을 공백 치환해야 정규식이 맞음.
- 표가 "번호 → 단어 → 뜻(여러 줄)" 순서로 흐르고, 번호 순서가 좌우 열 교차(1,26,2,27,…,25,50)라
  **기대 번호 시퀀스**를 추적하며 파싱.
- 숙어(word가 줄바꿈으로 뜻 칸에 섞인 경우: `first-come, first-served`, `be supposed to RV` 등)는
  "뜻의 선두 토큰이 한글도 품사표기도 아니면 단어로 이동" 규칙으로 복원 (총 34건 수정됨).
- 검증: 단어에 라틴 문자 존재 + 뜻에 한글 존재, 일자별 50개 정확히.

### 폰트 서브셋 (build.py)

- 사용 문자 = 템플릿 전체 + vocab.js 전체 + ASCII + `★☆·%` → 약 990자
- fontTools subset → woff2 (Regular/ExtraBold 각 ~155KB) → base64로 `@font-face`에 주입
- **주의**: UI 문구에 새 한글 글자를 추가하면 반드시 재빌드해야 그 글자가 폰트에 포함됨

## 프런트엔드 구조 (app_template.html 내 JS)

### 화면(섹션): `#screen-home` / `#screen-quiz` / `#screen-result` / `#screen-hist` / `#screen-note` + 오답 시트(`#answer-sheet`)

### localStorage 스키마 (키 프리픽스 `vocaQuest.`)

| 키 | 형태 | 설명 |
|---|---|---|
| `vocaQuest.best` | `{ [dayIdx]: {stars,pct,score} }` | DAY별 최고 기록 |
| `vocaQuest.srs` | `{ "d-i": {lv,due,rc,wc} }` | 망각곡선 카드. lv 0~5(5=마스터, due=null), due=epoch(ms), rc=성공 복습수, wc=오답수 |
| `vocaQuest.hist` | `[{t,type,day,label,total,correct,pct,score,maxCombo}]` | 완료 세션 기록 (최신순, 최대 300) |
| `vocaQuest.session` | 세션 스냅샷 | 이어하기용. questions 배열(재출제 포함)·idx·score·combo·correct·wrongQs·sched |
| `vocaQuest.mute` | '1'/'0' | 음소거 (효과음+자동TTS 모두) |
| (구) `vocaQuest.wrong` | 배열 | 로드 시 SRS 카드로 자동 마이그레이션 후 삭제 |

### 핵심 함수 맵

- 데이터: `VOCAB[day][i] = {w:단어, m:뜻}` (vocab.js)
- 세션: `startDay(d)` / `startReview()` / `startSession(cfg)` / `makeQuestions(list)`
  (오답 선택지는 같은 DAY에서 3개, 중복 뜻 제외, 부족하면 타 DAY에서 보충)
- 진행: `renderQuestion()` → `answer(i,btn)` → 정답: `proceedAfterSpeech(m,minDelay)` → `next()`
  / 오답: 재출제 push + `openSheet(q)` (수동 진행)
- SRS: `srsCorrect(key)` (due 지난 카드만 레벨업, 5레벨=마스터) / `srsWrong(key)` (lv0 리셋·생성)
  / `dueCards()` / 간격 `SRS_IV=[1,3,7,14,30]`일
- 이어하기: `saveSession(nextIdx)` (답변 직후 idx+1로 저장) / `loadSession()` / `resumeSession()` / `clearSession()`
- 기록: `logHistory(entry)` / `calcStreak()` / `renderHist()`
- 오디오: `unlockAudio()` (모든 제스처에 등록, iOS 무음버퍼 언락) / `beep()` (suspended면 resume 후 재생)
  / `sfx.correct/wrong/combo/tap/fanfare/levelup`
- 햅틱: `haptic.*` (`navigator.vibrate`, iOS 사파리는 미지원이라 무시됨)
- TTS: `speak(text,lang,rate,onend)` / `speakWord(w)` (en-US .92) / `speakMeaning(m,onend)` (ko-KR 1.02)
  / `cleanMeaning(m)` (품사표기·대괄호 제거, 괄호는 내용만, `;`→`,`)

### 주의해야 할 동작 규칙

- `S`(세션 객체)는 홈으로 나갈 때 `null` 처리 — 비동기 콜백은 `S === sess` 캡처 비교로 스테일 진행 방지
- 답변 시점에 `saveSession(S.idx+1)` — 시트/TTS 도중 이탈해도 다음 문제부터 복원
- 재출제 문제는 `q.re === true`: 점수 +5 고정, `S.correct`/정답률/별점에 미반영, 오답노트 중복 등록 안 함
- 정답률/별점은 **첫 시도 기준** (`questions.filter(q=>!q.re).length` 분모)
- DAY 셀 탭 시 해당 DAY의 일시정지 세션이 있으면 **새로 시작이 아니라 이어하기**

## 테스트 방법

Playwright + 프리셋 Chromium (`executablePath: '/opt/pw-browsers/chromium'`, CCR 환경 기준).
동봉된 `test3.js`(이어하기/기록), `test5.js`(자동 TTS 진행), `test6.js`(오답 시트/재출제)를
`node testN.js`로 실행. `file:///.../index.html` 직접 로드 방식.
헤드리스에는 TTS 음성이 없어 최소 대기시간 폴백으로 진행됨(안전장치 검증 겸함).

## 알려진 제약 / 메모
